NVDA Remote Audio Client

This add-on connects to NVDARemoteAudioServer to send or receive system audio between two Windows machines. NVDA speech itself stays on NVDA Remote; this add-on only carries everything else (music, games, Discord, browsers, etc.).

First-time setup

  1. Install this add-on on both machines.
  2. On the machine that should send audio: open NVDA menu > Tools > NVDA Remote Audio > Install audio server (this machine sends audio)... The add-on downloads the latest NVDARemoteAudioServer from GitHub, installs it, starts it, and registers a per-user logon task so it survives reboots. It will also prompt for UAC to add Windows Firewall inbound allow rules for TCP and UDP port 6838. If you decline UAC, run the helper menu item Add firewall rules for audio server... later, or open the port manually.
  3. On both machines, open NVDA menu > Preferences > Settings > NVDA Remote Audio.
  4. Set the same Host, Port (6838 by default), and Key on both.
  5. Restart NVDA, or use the Tools menu items to connect manually. If you skipped step 2, picking Send this computer's audio will offer to install the server then.

Inbound TCP and UDP port 6838 on the sending machine must be reachable by the receiving machine. Windows Firewall may prompt the first time the server runs, or you can pre-allow it.

How "Automatic" startup works

If C:\NVDARemoteAudioServer\NVDARemoteAudioServer.exe exists on a machine, that machine sends. Otherwise it receives. Override this by changing Startup action in settings.

Latency profiles

  • LAN — lowest buffer (30/40/200 ms).
  • Tailscale — small extra buffer (90/80/450 ms).
  • Internet — most stable low-latency buffer (150/120/800 ms).
  • Automatic — picked from the host you set: LAN for private/loopback IPs, Tailscale for 100.64.0.0/10 or *.ts.net, Internet for anything else.

Privacy

Publisher mode uses Windows process-loopback exclusion to drop NVDA from the captured audio, so NVDA speech and NVDA tones are not sent by this add-on. Other app audio is sent unencrypted over UDP — protect the link yourself (LAN, VPN, or Tailscale).
