NVDA Remote Audio Client

This add-on sends or receives secure low-latency audio between two Windows machines, and to and from the RemSound apps on Windows, iPhone, Android, and Mac. It can send all system audio except NVDA, isolate one selected application, or send a microphone. NVDA speech itself stays on NVDA Remote.

There are two connection types, chosen under Connection type in settings:

  • NVDA Remote Audio server — the default. Both machines connect to a relay server by host name, port 6838, and a shared room name.
  • RemSound peer to peer — this machine talks directly to a RemSound device. There is no server and no room name, only a shared encryption password. UDP port 47830 is used, with UDP 47821 for discovery.

Setup through the audio server

  1. Install this add-on on both machines.
  2. On the machine that should send audio: open NVDA menu > Tools > NVDA Remote Audio > Install audio server (this machine sends audio)... The add-on downloads the latest NVDARemoteAudioServer from GitHub, installs it, starts it, and registers a per-user startup entry so it survives reboots. It will also prompt for UAC to add Windows Firewall inbound allow rules for TCP and UDP port 6838. If you decline UAC, run the helper menu item Add firewall rules for audio server... later, or open the port manually.
  3. On both machines, open NVDA menu > Preferences > Settings > NVDA Remote Audio and leave Connection type on NVDA Remote Audio server.
  4. Set the same Host, Port (6838 by default), and Session key / room name on both. The key is required, but it is not an encryption password.
  5. Set the same End-to-end encryption password on both machines. This is strongly recommended.
  6. Optionally choose Audio to send on the sending machine and Receive through plus Receive volume on the receiving machine.
  7. Restart NVDA, or use the Tools menu items to connect manually. If you skipped step 2, picking Send this computer's audio will offer to install the server then.

Inbound TCP and UDP port 6838 on the sending machine must be reachable by the receiving machine. Windows Firewall may prompt the first time the server runs, or you can pre-allow it.

Setup with a RemSound device

  1. Set the same encryption password on both devices. RemSound always encrypts, so there is no unencrypted mode, and the settings panel will not save a RemSound connection without a password.
  2. On this computer, set Connection type to RemSound peer to peer.
  3. To choose devices by name, open NVDA menu > Tools > NVDA Remote Audio > Find RemSound devices on this network... with the RemSound app open on the other device, and tick it in the list. Each entry says whether the device sends, receives, or both, and lists every address it answered on. Choosing a device switches the connection type to RemSound for you.
  4. If discovery cannot reach the device — over Tailscale or the open internet, for example — type its address or Tailscale name into RemSound devices by address instead.
  5. In the other device's own RemSound app, tick this computer the same way it appears there, and make sure that app is actually sending its microphone — RemSound on a phone does not send until sending is switched on, and its per-device status text says which of the two is stopping it. Name other RemSound devices see for this computer changes what that name is.
  6. Choose Receive remote audio, Send this computer's audio, or Send and receive at the same time (RemSound). The two-way choice is the one to pick to talk to a phone in both directions; it is only offered on a RemSound connection, because the relay server carries audio one way.

This computer keeps one device identity for the life of the installation, so the other device only has to be set up once: it still recognizes this computer after a restart, and after this computer's address changes.

RemSound connections need no relay server and no port 6838 firewall rule. Allow UDP port 47830 on both devices, and UDP 47821 if you want discovery to find them. On an iPhone, allow the RemSound app local network access, or it cannot be found or reached.

How "Automatic" startup works

If C:\NVDARemoteAudioServer\NVDARemoteAudioServer.exe or %LOCALAPPDATA%\NVDARemoteAudioServer\NVDARemoteAudioServer.exe exists on a machine, that machine sends. Otherwise it receives. Override this by changing Startup action in settings. A RemSound connection never needs the server installed, and Send and receive at the same time (RemSound) is chosen explicitly rather than automatically.

Latency profiles

  • LAN — 5 ms Opus packets and the lowest buffer (15/15/120 ms).
  • Tailscale — 10 ms Opus packets with a small extra buffer (50/20/250 ms).
  • Internet — 10 ms Opus packets with the most stable low-latency buffer (100/30/600 ms).
  • Automatic — picked from the devices you set: LAN for the Windows default, private and loopback addresses, or any device found by discovery; Tailscale for 100.64.0.0/10 or *.ts.net; Internet for anything else.

Controls and status

The Tools menu provides receive, send, send and receive at the same time, reconnect, disconnect, status, this computer's address, find RemSound devices, copy diagnostics, server install, server update/repair, firewall, server remove/disable, and settings actions. Receive, send, send and receive at the same time, disconnect, reconnect, status, this computer's address, find RemSound devices, copy diagnostics, and every volume and remote-control command are also available as unbound NVDA Input Gestures under the NVDA Remote Audio category. While you are controlling another machine with NVDA Remote, those gestures stay local instead of being forwarded as keystrokes. Nothing in this list is given a default key, so no existing shortcut is taken over.

This computer's address for the other computer speaks and copies this machine's Tailscale address, local network address, computer name, and port, so you can set up the other computer without leaving NVDA to look them up.

Find RemSound devices on this network... listens for a few seconds and lists every RemSound device that answered, saying for each one whether it sends, receives, or both, and every address it answered on. Devices are grouped by name, so a phone that answers on both Wi-Fi and Tailscale appears once. Tick the devices to use and the connection type becomes RemSound if it was not already. The list is a standard multi-select list, so space bar and the arrow keys are all you need.

Received volume, mute, and the other device's volume can be changed from a gesture while audio is running, with no reconnect and no return to settings. Raise/Lower/Mute received remote audio affect what you hear. Raise/Lower the other device's RemSound volume, Mute or unmute RemSound on the other device, and the three matching Windows-volume commands ask the other device to change, and only work if that device has allowed remote control. Lowering the receive volume while nothing is playing changes the saved level for the next connection instead of doing nothing.

If the relay server restarts or a network heartbeat fails, the helper releases the old audio and network session and reconnects automatically. A manual reconnect is still available when you change routing or connection settings.

In settings, clear Announce connection status messages to keep routine connect/listen/capture/stopped messages quiet. Errors and explicit status commands still speak. Use Opus packet-loss recovery controls Opus in-band FEC, which is enabled by default. Enable Verbose diagnostic logging when you need helper timing details in NVDA's log.

Audio to send defaults to all system audio with NVDA excluded. To send one application, start it and make it play or open audio before opening settings. If that application restarts, reconnect remote audio so its new process is selected. To send a microphone instead — the way a phone hears this computer — choose Microphone: Windows default recording device or a named recording device from the same list. Receive through can follow the Windows default or pin playback to an active endpoint. When it follows the Windows default, it keeps following it for the whole session: unplugging headphones, a Bluetooth headset dropping, or changing the Windows output moves playback to the device that is now current instead of leaving it on the old one. Receive volume ranges from 0 to 200 percent; 100 percent is unchanged.

Audio quality offers adaptive Opus, 5 ms live Opus, broadcast-quality Opus, and uncompressed PCM. On a RemSound connection the same choices are used with RemSound's own encoding: Opus at 48 kHz stereo, or 24-bit PCM in 2.5 ms frames, with the format re-announced four times a second so a device that joins late still starts playing. The receiver also has pan and three-band bass, midrange, and treble controls. Received audio can be recorded to timestamped WAV files. Named connection profiles can be saved, loaded, and deleted from the Tools menu, and they remember the connection type and the RemSound devices you chose.

When the two computers disagree

If the sending computer's add-on is a different version and the two can no longer understand each other's audio, the receiving computer says so and names which computer to update, instead of simply going quiet. A wrong end-to-end encryption password, audio damaged on the network, and a version mismatch are reported as three separate problems, because each is fixed in a different place. A single packet damaged in transit is never enough to end a session. A RemSound sender whose password differs is reported the same way, as a password problem rather than silence.

Privacy and remote control

Publisher mode uses Windows process-loopback exclusion to drop NVDA from the system mix, or process-loopback inclusion to isolate the selected application's process tree. When a password is set, every audio packet is encrypted and authenticated end to end with AES-256-GCM; the relay cannot hear it, and a RemSound peer cannot hear it without the same password. Leaving the password empty enables unencrypted compatibility mode and should only be used on trusted networks or inside a VPN — but only on the audio-server connection type, because RemSound has no unencrypted mode.

Another device can change this computer's Windows volume only if Let RemSound devices that share the password change this computer's volume is ticked on this computer. Those requests are sealed with the audio key, refused if they are more than ten minutes old, and refused if they are replayed. Leave the setting off and no RemSound peer can touch this computer's volume at all.
