NVDA Remote Audio Client

This add-on connects to NVDARemoteAudioServer to send or receive secure low-latency audio between two Windows machines. It can send all system audio except NVDA or isolate one selected application. NVDA speech itself stays on NVDA Remote.

First-time setup

  1. Install this add-on on both machines.
  2. On the machine that should send audio: open NVDA menu > Tools > NVDA Remote Audio > Install audio server (this machine sends audio)... The add-on downloads the latest NVDARemoteAudioServer from GitHub, installs it, starts it, and registers a per-user startup entry so it survives reboots. It will also prompt for UAC to add Windows Firewall inbound allow rules for TCP and UDP port 6838. If you decline UAC, run the helper menu item Add firewall rules for audio server... later, or open the port manually.
  3. On both machines, open NVDA menu > Preferences > Settings > NVDA Remote Audio.
  4. Set the same Host, Port (6838 by default), and Session key / room name on both. The key is required, but it is not an encryption password.
  5. Set the same End-to-end encryption password on both machines. This is strongly recommended.
  6. Optionally choose Audio to send on the sending machine and Receive through plus Receive volume on the receiving machine.
  7. Restart NVDA, or use the Tools menu items to connect manually. If you skipped step 2, picking Send this computer's audio will offer to install the server then.

Inbound TCP and UDP port 6838 on the sending machine must be reachable by the receiving machine. Windows Firewall may prompt the first time the server runs, or you can pre-allow it.

How "Automatic" startup works

If C:\NVDARemoteAudioServer\NVDARemoteAudioServer.exe or %LOCALAPPDATA%\NVDARemoteAudioServer\NVDARemoteAudioServer.exe exists on a machine, that machine sends. Otherwise it receives. Override this by changing Startup action in settings.

Latency profiles

  • LAN — 5 ms Opus packets and the lowest buffer (15/15/120 ms).
  • Tailscale — 10 ms Opus packets with a small extra buffer (50/20/250 ms).
  • Internet — 10 ms Opus packets with the most stable low-latency buffer (100/30/600 ms).
  • Automatic — picked from the host you set: LAN for private/loopback IPs, Tailscale for 100.64.0.0/10 or *.ts.net, Internet for anything else.

Controls and status

The Tools menu provides receive, send, reconnect, disconnect, status, this computer's address, copy diagnostics, server install, server update/repair, firewall, server remove/disable, and settings actions. Receive, send, disconnect, reconnect, status, this computer's address, and copy diagnostics are also available as unbound NVDA Input Gestures under the NVDA Remote Audio category. While you are controlling another machine with NVDA Remote, those gestures stay local instead of being forwarded as keystrokes.

This computer's address for the other computer speaks and copies this machine's Tailscale address, local network address, computer name, and port, so you can set up the other computer without leaving NVDA to look them up.

Version 0.2.2 safely removes the stale Remote Audio menu item while retaining its detached wx wrapper until NVDA exits, preventing Reload Add-ons from terminating NVDA.

If the relay server restarts or a network heartbeat fails, the helper releases the old audio and network session and reconnects automatically. A manual reconnect is still available when you change routing or connection settings.

In settings, clear Announce connection status messages to keep routine connect/listen/capture/stopped messages quiet. Errors and explicit status commands still speak. Use Opus packet-loss recovery controls Opus in-band FEC, which is enabled by default. Enable Verbose diagnostic logging when you need helper timing details in NVDA's log.

Audio to send defaults to all system audio with NVDA excluded. To send one application, start it and make it play or open audio before opening settings. If that application restarts, reconnect remote audio so its new process is selected. Receive through can follow the Windows default or pin playback to an active endpoint. When it follows the Windows default, it keeps following it for the whole session: unplugging headphones, a Bluetooth headset dropping, or changing the Windows output moves playback to the device that is now current instead of leaving it on the old one. Receive volume ranges from 0 to 200 percent; 100 percent is unchanged.

Audio quality offers adaptive Opus, 5 ms live Opus, broadcast-quality Opus, and uncompressed PCM. The receiver also has pan and three-band bass, midrange, and treble controls. Received audio can be recorded to timestamped WAV files. Named connection profiles can be saved, loaded, and deleted from the Tools menu.

When the two computers disagree

If the sending computer's add-on is a different version and the two can no longer understand each other's audio, the receiving computer says so and names which computer to update, instead of simply going quiet. A wrong end-to-end encryption password, audio damaged on the network, and a version mismatch are reported as three separate problems, because each is fixed in a different place. A single packet damaged in transit is never enough to end a session.

Privacy

Publisher mode uses Windows process-loopback exclusion to drop NVDA from the system mix, or process-loopback inclusion to isolate the selected application's process tree. When a password is set, every audio packet is encrypted and authenticated end to end with AES-256-GCM; the relay cannot hear it. Leaving the password empty enables unencrypted compatibility mode and should only be used on trusted networks or inside a VPN.
