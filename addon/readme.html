NVDA Remote Audio Client

This add-on connects to NVDARemoteAudioServer to send or receive system audio between two Windows machines. NVDA speech itself stays on NVDA Remote; this add-on only carries everything else (music, games, Discord, browsers, etc.).

First-time setup

  1. Install this add-on on both machines.
  2. On the machine that should send audio: open NVDA menu > Tools > NVDA Remote Audio > Install audio server (this machine sends audio)... The add-on downloads the latest NVDARemoteAudioServer from GitHub, installs it, starts it, and registers a per-user Startup shortcut so it survives reboots. It will also prompt for UAC to add Windows Firewall inbound allow rules for TCP and UDP port 6838. If you decline UAC, run the helper menu item Add firewall rules for audio server... later, or open the port manually.
  3. On both machines, open NVDA menu > Preferences > Settings > NVDA Remote Audio.
  4. Set the same Host, Port (6838 by default), and Key on both.
  5. Restart NVDA, or use the Tools menu items to connect manually. If you skipped step 2, picking Send this computer's audio will offer to install the server then.

Inbound TCP and UDP port 6838 on the sending machine must be reachable by the receiving machine. Windows Firewall may prompt the first time the server runs, or you can pre-allow it.

How "Automatic" startup works

If C:\NVDARemoteAudioServer\NVDARemoteAudioServer.exe or %LOCALAPPDATA%\NVDARemoteAudioServer\NVDARemoteAudioServer.exe exists on a machine, that machine sends. Otherwise it receives. Override this by changing Startup action in settings.

Latency profiles

  • LAN — 5 ms Opus packets and the lowest buffer (15/15/120 ms).
  • Tailscale — 10 ms Opus packets with a small extra buffer (50/20/250 ms).
  • Internet — 10 ms Opus packets with the most stable low-latency buffer (100/30/600 ms).
  • Automatic — picked from the host you set: LAN for private/loopback IPs, Tailscale for 100.64.0.0/10 or *.ts.net, Internet for anything else.

Controls and status

The Tools menu provides receive, send, reconnect, disconnect, status, server install, firewall, and settings actions. Receive, send, disconnect, reconnect, and status are also available as unbound NVDA Input Gestures under the NVDA Remote Audio category. While you are controlling another machine with NVDA Remote, those gestures stay local instead of being forwarded as keystrokes.

In settings, clear Announce connection status messages to keep routine connect/listen/capture/stopped messages quiet. Errors and explicit status commands still speak. Use Opus packet-loss recovery controls Opus in-band FEC, which is enabled by default. Enable Verbose diagnostic logging when you need helper timing details in NVDA's log.

Privacy

Publisher mode uses Windows process-loopback exclusion to drop NVDA from the captured audio, so NVDA speech and NVDA tones are not sent by this add-on. Other app audio is sent unencrypted over UDP — protect the link yourself (LAN, VPN, or Tailscale).
